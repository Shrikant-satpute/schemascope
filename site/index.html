You ship one schema to every client. A hotfix lands in one, a release skips another, someone edits a procedure in a third. Months later nobody can say which client is missing which table, procedure or schema, until a deploy fails.

Write mode · new in 1.2

Read-only, until you say otherwise.

SchemaScope never changes a database on its own. Applying scripts takes a switch you turn on for this session, and every apply asks again.

Write mode Off
  • Off at every launchNever saved. Turning it on takes a confirmation, and it switches itself off after 30 idle minutes.
  • Type the database nameBefore every apply. It is checked against the connection, and again on the server itself.
  • Protected servers are refusedMark a connection Protected and SchemaScope will only ever write scripts for it, however the server name is typed.
  • One file, one transactionIf a file fails, that file is rolled back and the run stops there. The files before it stay applied, and you are told which.
  • Edited scripts are refusedEvery file is hash-checked before it runs, so what you reviewed is exactly what runs.
  • Compares again, and logs itThe new score appears straight away. Every apply is recorded on your PC: when, where, which files, and the result.

Security & privacy

Your schema stays on your machine.

Built for people whose schema is not allowed to leave the building. Each of these is a mechanism you can check in the source.

No telemetry. No update check.

None at all. The only outgoing connections are to the databases you named.

Passwords encrypted with Windows DPAPI.

Scoped to your Windows account, and only ever used for the server and login they were saved with.

The local API answers only its own window.

Loopback only, a token minted at startup on every call, and other host names refused.

Shared links are read-only.

Nothing listens on your network until you press Share. Links never write, and expire after 7 days or when you press Stop.

Open source, built in public. Every release is built by GitHub Actions from a tagged commit and ships a SHA256SUMS.txt.

FAQ

Questions, answered plainly.

Can it change my database?

Only if you ask it to. SchemaScope is read-only by default. Create scripts writes SQL files to a folder and checks them offline; you can review them and run RUN.ps1 yourself, ideally on a rehearsal copy first.

To apply them from the app, switch on Write mode. It is off every time SchemaScope starts, turns itself off after 30 idle minutes, asks you to type the target database's name before every apply, and refuses any connection marked Protected. Each file runs in its own transaction and stops at the first error; files before it stay applied. It runs as the target connection's login, so use one with no more rights than the change needs.

Is it really free?

Yes. SchemaScope is free and open source under the Apache-2.0 licence, with no account, no trial and no paid tier. It is built by Shadowmark. Issues and contributions are welcome on GitHub.

Which SQL Server versions does it support?

SQL Server 2012 and later, Azure SQL Database, Azure SQL Managed Instance and AWS RDS. You can sign in with Windows, a SQL login, or Microsoft Entra (password, interactive MFA, or default).

How fast will it be on my servers?

Most of the time goes into reading each database's catalog, and all targets are read at the same time, so the slowest server sets the pace. On our demo, nine targets took under a second. The first run after starting the app is slower; later runs reuse cached object text that has not changed.

What permissions does the login need?

VIEW DEFINITION to read. Without it SchemaScope still sees object names, and marks bodies it cannot read as Unreadable instead of reporting a false difference. Applying scripts needs whatever rights the changes themselves need.

Does it migrate data?

No. Scripts change structure only. Changes that existing data could break are held back in 99_review with the reason, and changes that can lose data are only scripted when you opt in.

Why does Windows say "Windows protected your PC"?

The binaries are not code-signed yet, so SmartScreen does not recognise them. Click More info, then Run anyway, or check the file against the release's SHA256SUMS.txt first. Installing through Scoop avoids the prompt.

Does it run on macOS or Linux?

No, Windows 10 and 11 only. Teammates on other systems can still open a shared read-only link in their browser.
