Six answers, not two

A re-indented procedure is not a change.

Most tools say "same" or "different", which reports reformatted code as drift and buries the differences that matter. SchemaScope separates them, and never hides anything: an ignore rule moves an object down a level rather than making it disappear. Every status has a symbol and a word as well as a colour.

=

Same

Identical to the source. Settled by hash, never looked at again.

~

Formatting

Same code. Only spacing, comments or brackets moved.

≠

Different

A real difference, with the number of changed lines beside it.

✕

Missing

In the source, but not in this target. A release that did not land.

+

Extra

Only in this target. Usually somebody's local change.

?

Unreadable

Encrypted, or your login lacks VIEW DEFINITION. Said plainly, never guessed.

New in 1.1

Create scripts

Click the script icon on any target's tile. You get numbered folders of SQL that make that target look like the source, with a README to read first.

  • Checked offline. Every batch is parsed, and procedure and view bodies are compared byte for byte with the source before you run anything.
  • Risky changes held back. NOT NULL columns with no default, keys existing data would break, code that would not compile: listed in 99_review with the reason, not scripted.
  • Safe defaults. Table types, triggers and changed code are off by default, and come with undo scripts. Column types are never narrowed.
  • No secrets in the folder. RUN.ps1 runs under your Windows login, so no connection details are written to any file.

Why not Visual Studio?

Security & privacy

Your schema stays on your machine.

SchemaScope is for people whose schema is not allowed to leave the building. Every one of these is a mechanism you can check in the source, not a line in a policy.

Read-only, structurally.

There is no code path that writes to a database. Scripts are generated and checked offline, never run by the app.

Passwords encrypted with Windows DPAPI.

Stored in %LOCALAPPDATA%\SchemaScope, scoped to your Windows account. A saved password is only used for the server and login it was saved with.

The local API answers only its own window.

It listens on loopback, every call carries a token minted at startup, and requests addressed to any other host name are refused.

The browser engine blocks outside requests.

The UI runs under Content-Security-Policy: default-src 'self'. A request to another host is refused before it is made.

No telemetry. No update check.

Not "anonymised analytics" — none. The only outgoing connections are to the databases you named.

Object text cached locally, never data.

Bodies are cached in %LOCALAPPDATA%\SchemaScope\cache. Delete the folder and the only cost is the next run's time.

What changes when you share

Nothing listens on your network until you press Share. Then SchemaScope starts a second, read-only listener on port 5280, and stops it when the last link is stopped or expires, or when you close the app.

  • It serves only the shared snapshot. Your connections, passwords, history and the compare and script features are not on it — they stay on the token-protected loopback API.
  • The link is the key. Anyone on your network who has it can read the full text of every object in that comparison, plus server and database names, over plain HTTP. Share it the way you would share the .sql files.
  • Links expire after 7 days, or when you press Stop.
  • Letting teammates through Windows Firewall needs administrator rights; the Share tab shows the exact rule first.

Installing

Two clicks to a desktop icon.

  1. Download the installer

    Everything is bundled — no .NET install, nothing to unpack.

  2. Run it

    It installs for your account only, so Windows never asks for administrator rights. Tick the box for a desktop shortcut.

  3. Point it at your databases

    Add one source and as many targets as you like. A login with VIEW DEFINITION is all it needs:

    GRANT VIEW DEFINITION TO [your_login];

Prefer nothing installed?

SchemaScope.exe is the portable build: one self-contained file, no .NET install, no files beside it.

Use Scoop?

Installs the portable build, keeps it current with scoop update, and skips the SmartScreen prompt.

scoop install https://raw.githubusercontent.com/Shrikant-satpute/schemascope/main/packaging/scoop/schemascope.json

Windows will warn you on first run

SchemaScope is not code-signed yet, so SmartScreen shows "Windows protected your PC". Click More info, then Run anyway.

More info→Run anyway

You do not have to take that on trust. Every release is built in public by GitHub Actions from the tagged commit, and ships a SHA256SUMS.txt you can check:

Get-FileHash .\SchemaScope-Setup.exe -Algorithm SHA256

WebView2 is required and ships with Windows 10 and 11. If it is somehow missing, you get a plain explanation and a download link.

FAQ

Questions, answered plainly.

Why does Windows say "Windows protected your PC"?

The binaries are not code-signed yet, so SmartScreen does not recognise them. Click More info, then Run anyway. If you would rather check first, compare the file against the SHA256SUMS.txt on the release — every release is built by GitHub Actions from the tagged commit. Installing through Scoop avoids the prompt altogether.

Do I need administrator rights?

No. The installer is per-user, and the portable build needs no install at all. The one exception is optional: if you share a comparison and teammates cannot reach it, adding the Windows Firewall rule needs an administrator.

Which SQL Server versions does it support?

SQL Server 2012 and later, Azure SQL Database, Azure SQL Managed Instance and AWS RDS. The catalog queries adjust to the server version. You can sign in with Windows, a SQL login, or Microsoft Entra (password, interactive MFA, or default).

What permissions does the login need?

VIEW DEFINITION. Without it SchemaScope still sees object names but not their bodies, and marks those objects Unreadable instead of reporting a false difference. The connection test warns you up front.

Can it change my database?

No. There is no code that writes to a database. Create scripts writes SQL files to a folder and checks them offline; you review them and run RUN.ps1 yourself, ideally on a rehearsal copy first.

Does it migrate data?

Not in this version. Scripts change structure only. Changes that existing data could break are held back in 99_review with the reason, instead of being scripted.

Who can open a shared link?

Anyone who has the link and can reach your PC on the network. They get a read-only view of that one comparison, including the full text of its objects. Links expire after 7 days or when you press Stop, and only work while your PC is awake and SchemaScope is open.

Does it run on macOS or Linux?

No — Windows 10 and 11 only. Teammates on other systems can still open a shared read-only link in their browser.

What does it cost?

Nothing. SchemaScope is free and open source under the Apache-2.0 licence, built by Shadowmark. Issues and contributions are welcome on GitHub.
